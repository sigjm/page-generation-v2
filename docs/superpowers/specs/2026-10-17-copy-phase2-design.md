# 초안 문구 개선 설계 (2단계)

- 작성: 2026-10-17
- 상태: 사용자 검토 대기
- 기반:
  - `2026-10-16-conversational-detail-page-agent-design.md`
  - `2026-10-16-judge-finetune-design.md`(1단계)
  - `docs/finetune/2026-10-17-judge-r3-report.md`
- 1단계 결과: 판정은 원본 9B 그대로 둔다. 판정 파인튜닝은 기록으로만 남긴다.

## 1. 목표

초안 문구(`write_copy`)를 아래 네 가지 면에서 낫게 만든다. 지금 원본 9B의 초안 600개(1단계 데이터, 상품 300개 × 2회)를 재 보면 이렇다.

- **반복·베끼기**
  - 71%의 초안에 프롬프트 예시 "아침 햇살"이 들어 있다. "아침 햇살이 드는 원목 식탁 위"라는 문장만 104번 나온다.
  - 29%의 초안이 "관리 및 주의 사항" 같은 이름표 제목을 쓴다.
- **지어낸 사실:** 판매자 설명에 없는 관리 문구, 사진에서만 보이는 부품의 기능, "무향"·"저자극" 같은 소재·효능을 지어낸다. 이런 문장은 검사에서 빠지고, 그만큼 페이지가 얇아진다.
- **더 팔리는 문구:** 혜택 중심의 문구, 상품마다 다른 개성.
- **분류별 말투:** 식품, 화장품, 가전·전자, 의류·잡화, 생활·주방에 각각 어울리는 표현.

진행은 두 단계로 나눈다.

- **2-1:** 학습 없이 프롬프트와 검사를 고친다.
- **2-2:** Codex 교사가 2-1보다 확실히 나을 때만 LoRA SFT를 한다.

### 합격 기준 (각 단계 공통, 시험용 상품 30개, §3)

| 지표 | 기준 |
|---|---|
| 블라인드 비교 | 새 초안이 이긴 비율 ≥ 60% (비슷함은 빼고 셈) |
| 기계 지표(§3.3) | 하나도 허용 폭을 넘어 나빠지지 않음 |
| `scripts/eval_tools.py` | 도구 11/13 이상, 판정 8/8 |
| 초안 한 번 만드는 시간(2-2만) | 기준선의 1.5배 이하 |

2-1은 지금 `COPY_SYSTEM`과 비교한다. 2-2는 2-1과 비교한다. 못 미치면 채택하지 않고 결과를 기록으로 남긴다.

### 범위 밖

- 대화·도구 호출 학습
- 판정 모델 변경
- 이미지 생성·편집
- 레이아웃
- 실제 사용자 데이터(`projects/`)로 학습

## 2. 결정 요약

| 항목 | 결정 | 이유 |
|---|---|---|
| 접근 | 프롬프트 먼저(2-1), 학습은 조건부(2-2) | 예시 베끼기 같은 문제는 프롬프트로 고칠 수 있다. 기준선이 낮으면 학습 효과가 부풀려 보인다 |
| 평가 판정자 | 맥락 없는 새 Claude 서브에이전트, 블라인드 A/B | 사용자 선택. 교사(Codex)와 판정자를 나눈다 |
| 교사 | Codex(`codex exec`) | 판정자와 달라야 한다. 1단계와 같은 도구를 재사용한다 |
| 관문 | 학습 전에 교사 초안이 2-1을 이긴 비율 ≥ 70% | 1단계 교훈: 학생은 교사를 따라간다 |
| 런타임 | `COPY_MODEL`(기본값 원본 9B). `write_copy`만 사용 | 대화·도구·판정은 바뀌지 않는다 |
| 병합 | 8bit | 1단계에서 4bit 병합이 LoRA를 지웠다 |

## 3. 평가 장치

### 3.1 상품

1단계의 가상 상품 300개(분류 5개 × 60개)를 그대로 쓴다.

| 용도 | 상품 | 쓰는 곳 |
|---|---|---|
| 개발용 | 분류마다 1~6번째(30개) | 2-1 프롬프트 반복, 2-2 관문과 검증 |
| 시험용 | 분류마다 13~18번째(30개) | 각 단계의 채택 판정에 한 번만 |
| 학습용 | 나머지 240개 | 2-2 교사 초안 |

판정 시험셋 상품(7~12번째)은 문구 시험에 쓰지 않는다. 그 상품들의 9B 문장은 이미 읽었고, §4의 금지 유형도 거기서 나왔다. 이 상품들은 학습용에 들어간다.

### 3.2 초안 만들기

- 입력: 상품명, 판매자 설명, 사진 분석(분류·보이는 특징·색). 1단계 `judge_data.cmd_sentences`와 같다.
- 사진 설명이 없으므로 `details`는 빈 목록이다.
- 런타임 함수를 그대로 부른다: `write_copy` 메시지 → `build_sections` → `_clean`(숫자·최상급·한자·원본 판정).
- 이미지 생성·편집은 하지 않는다.
- 결과로 상품마다 아래 셋을 저장한다.
  - 모델이 쓴 원래 JSON
  - 검사 뒤 섹션
  - 걸린 문장과 이유

### 3.3 기계 지표

| 지표 | 정의 | 허용 폭 |
|---|---|---|
| 예시 베끼기 | 그 단계 프롬프트(기준선·새 프롬프트 모두)의 따옴표 속 예시 문구가 그대로 든 초안 비율 | +2%p |
| 상품 간 중복 | 30개 중 3개 이상의 초안에 똑같이 나온 문장의 비율 | +2%p |
| 이름표 제목 | 안내(`notice`)를 뺀 섹션에서 모델이 쓴 제목 중 `copy_eval.LABEL_HEADINGS`(주요 특징, 제품 특징, 이래서 좋아요, 사용 방법, 사용 전 확인하세요, 관리 및 주의 사항 등)에 드는 비율 | +2%p |
| 한자 | 검사 전 원래 JSON에 한자가 든 초안 수 | +1개 |
| 지어낸 사실 | 모델이 쓴 문장 중 검사에서 빠진 비율 | +2%p |
| 페이지 두께 | 검사 뒤 초안마다 남은 문장 수의 평균 | −10% |

### 3.4 블라인드 비교

1. `copy_eval pairs`가 두 파일을 쓴다.
   - `pairs.jsonl`: id, 분류, 근거 텍스트, A의 검사 뒤 문구, B의 검사 뒤 문구. A/B는 상품마다 무작위로 정하고, 시드는 고정한다.
   - `pairs-key.json`: 어느 쪽이 새것인지 적은 열쇠.
2. 판정은 Agent 도구로 띄운 새 Claude 서브에이전트(가장 성능 좋은 모델)가 한다.
   - 서브에이전트에게는 `pairs.jsonl`과 아래 채점 기준만 준다. 열쇠 파일, 프롬프트, 이 스펙은 주지 않는다.
   - 답은 `verdicts.jsonl`에 쓴다: id, 승자(A/B/비슷함), 한 줄 이유.
3. 채점 기준(고정)은 아래 순서로 따진다.
   1. 근거 텍스트에 없는 제품 사실을 말하는 쪽은 진다.
   2. 이 분류의 상품을 사고 싶어지게 하는가: 혜택이 분명한가, 이 상품만의 개성이 있는가.
   3. 분류에 어울리는 말투인가.
   4. 자연스러운 한국어인가: 반복, 베낀 듯한 상투구, 이름표 제목이 없는가.
4. `copy_eval score`가 열쇠로 승패를 풀어 기준과 비교하고, 기계 지표와 함께 표로 낸다.

## 4. 2-1: 프롬프트와 검사

| 문제 | 바꾸는 것 |
|---|---|
| 예시 베끼기 | `COPY_SYSTEM`에서 실제 장면 예시 문장을 빼고 "상품의 쓰임·색에 맞는 구체적인 장소를 상품마다 다르게"로 바꾼다. `build_sections`·`_clean`에서 장면 제목·본문이 `photo_instruction`과 같으면 그 문장을 뺀다 |
| 이름표 제목 | 금지 예시를 명시한다(안내 섹션은 예외). 지표가 줄지 않을 때만 검사를 추가한다 |
| 분류별 말투 | `COPY_SYSTEM`에 5개 분류마다 한 줄씩 말투 지침을 넣는다. 모델이 사진 분석의 `category`를 보고 고른다. 분류를 매핑하는 코드는 만들지 않는다 |
| 지어낸 사실 | 금지 유형을 넣는다: 판매자 설명에 없는 관리·주의 문구, 사진에서만 보이는 부품의 기능, 새로 붙인 소재·인증·효능, 효과·문제 해결을 단정하는 말 |
| 한자 | "한글로만 쓴다"를 넣는다 |

- 고치고 개발용 30개로 재는 일을 **최대 3번** 반복한다. 그다음 시험용 30개로 한 번 판정한다.
- 기준선은 지금의 `COPY_SYSTEM`으로, 같은 상품에서 런타임 호출 그대로 만든다.
- 2-1이 채택되면 런타임 프롬프트가 되고, 2-2의 기준선이 된다.
- 2-1이 채택되지 않으면 2-2는 지금의 `COPY_SYSTEM`을 기준선으로 삼는다.

## 5. 2-2: 조건부 SFT

### 5.1 교사 초안

- `codex_teacher.py`에 `copy` 명령을 더한다.
  - 기존 `call_codex`를 그대로 쓴다(읽기 전용 샌드박스, 캐시, 재시도).
  - 출력 스키마는 `prompts.COPY_SCHEMA`다.
- 지시문은 런타임과 같은 메시지다.
  - 메시지를 만드는 부분은 `agent.copy_messages(seller, analysis, hint)`로 뺀다. `write_copy`와 학습 데이터가 같은 함수를 쓴다(`judge_messages`와 같은 방식).
  - Codex 쪽에는 "JSON 하나로만 답한다"만 덧붙인다.
- 학습용 240개 상품마다 따로 두 번 물어 약 480개 초안을 만든다.
- 교사 초안도 §3.2의 검사를 그대로 거친다.
  - 한 문장이라도 걸린 초안은 버린다.
  - 남은 초안이 300개보다 적으면, 걸린 이유를 붙여 그 상품만 한 번 더 묻는다.
  - 버린 비율은 보고한다.
- 개발용·시험용 상품 이름이 교사 지시문 상수에 들어가면 테스트가 실패한다.

### 5.2 관문

Codex가 개발용 30개 상품의 초안을 쓰고, 2-1 기준선과 §3.4로 블라인드 비교한다.

- **교사가 이긴 비율이 70% 이상이고, 기계 지표가 허용 폭 안일 때만 학습한다.**
- 못 미치면 학습하지 않고 보고한다.

### 5.3 학습·병합

- mlx-vlm 0.7.8 LoRA SFT. 1단계와 같은 설정이다: rank 16, alpha 32, 학습률 5e-5, 응답 부분만 학습, grad checkpoint.
- 2 epoch로 돌린다.
- `max-seq-length`는 학습 행의 최대 토큰 수를 재서 정한다(2048 또는 3072).
- 검증은 개발용 상품의 교사 초안으로 한다.
- `fuse_lora.py --bits 8`로 병합하고, MLX Serve 앱을 다시 띄운 뒤 `/v1/models`에서 확인한다.

### 5.4 런타임

- `llm.COPY_MODEL`은 환경 변수 `COPY_MODEL`에서 읽고, 기본값은 텍스트 모델이다. `write_copy`만 `model=llm.COPY_MODEL`로 부른다.
- `copy_eval drafts --model`은 MLX Serve 목록에 없는 모델이면 멈춘다(`eval_judge.served_models` 재사용).
- 채택되면 README에 `COPY_MODEL` 설정을 적는다.

## 6. 분담

| 누가 | 맡는 것 |
|---|---|
| Codex(옆 창) | `codex_teacher.py`의 `copy` 명령. 교사로서 `codex exec` 실행 |
| Claude | `scripts/copy_eval.py`, 2-1 프롬프트·검사, `copy_messages`·`COPY_MODEL`, 서브에이전트 판정 운영, 학습·병합, 결과 판정·보고서·커밋 |

## 7. 위험과 대응

| 위험 | 대응 |
|---|---|
| Claude가 지침도 쓰고 판정도 해서 Claude 취향으로 치우침 | 판정자는 맥락 없는 서브에이전트이고 채점 기준은 고정한다. 객관적인 부분은 기계 지표로 받친다. 보고서에 이 한계를 적는다 |
| 상품 30개라 승률의 잡음이 큼 | 승·패·비슷함 개수를 그대로 보고한다. 60%는 최소선이다 |
| 2-1이 개발용 상품에만 맞춰짐 | 반복은 최대 3번. 시험용은 판정할 때 한 번만 연다 |
| Codex 문체 쪽으로 치우친 학습 | 학습 전에 관문으로 확인한다 |
| 원본 판정의 잘못 거르기(0.057)가 좋은 교사 초안까지 버림 | 버린 비율을 보고한다. 300개 미만이면 다시 묻는다 |
| MLX Serve가 모델을 번갈아 올려서 느려짐 | 초안 시간 기준(1.5배)을 둔다 |
| Codex 사용량 | 약 510번 호출(초안 480 + 관문 30, 재시도 별도). 캐시로 다시 실행할 때 재사용한다 |

## 8. 진행과 보고

1. 2-1 구현 → 개발용 반복(최대 3번) → 시험용 판정 → 보고
2. 2-2 교사 초안 → 관문 → (통과 시) 학습·병합 → 시험용 판정 → 보고

각 단계의 채택 여부는 §1 기준대로 정한다. 기준을 바꾸는 일은 사용자가 정한다. LangSmith에는 개발·학습용 가상 데이터만 보낸다.

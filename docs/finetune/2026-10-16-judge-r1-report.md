# 판정 모델 파인튜닝 결과 (r1·r2, 2026-10-17)

## 결론

**r1·r2 모두 채택하지 않습니다. 판정은 원본 9B 그대로 둡니다(`JUDGE_MODEL` 미설정).**

두 모델 모두 근거 없는 문장을 원본보다 훨씬 많이 잡지만(재현율 0.46 → 0.84~0.93), 근거 있는 문장도 많이 거릅니다(잘못 거르는 비율 0.034 → 0.135~0.225). 실모델 회귀 검사의 판정도 6/8입니다. 합격 기준(스펙 §1)의 "잘못 거르는 비율 ≤ 원본"과 "판정 8/8"을 둘 다 넘지 못합니다.

### 4bit 병합이 학습을 지웠습니다

계획대로 원본과 같은 4bit로 다시 양자화하며 병합한 r1은 원본과 거의 같았습니다(150문장 중 132문장 판정 동일). 같은 검증 200행에서 비교하면 이렇습니다.

| | 정밀도 | 재현율 | F1 |
|---|---|---|---|
| r1 어댑터(병합 전) | 0.723 | 0.896 | 0.800 |
| r1 4bit 병합 | 0.952 | 0.299 | 0.455 |
| r1 8bit 병합 | 0.723 | 0.896 | 0.800 |

LoRA가 바꾼 양이 4bit 양자화 간격보다 작아 대부분 반올림으로 사라진 것입니다. `fuse_lora.py`는 이제 언어 모델을 8bit로 다시 양자화합니다(비전 부분은 원본처럼 양자화하지 않음). 모델 크기는 9.7GB이고, 평가 지연은 원본과 같았습니다.

### 그 밖에 겪은 일

- MLX Serve는 목록에 없는 모델 이름을 받으면 오류 대신 이미 올라와 있는 모델로 답합니다. 새 폴더는 앱을 다시 띄워야 목록에 나타납니다. 처음 돌린 r1 평가는 그래서 원본의 결과였습니다(150/150 동일).
- LoRA 학습 중에 평가를 돌리면 MLX Serve가 GPU 메모리 부족으로 요청을 거절합니다(150문장 중 33문장 실패). 평가는 학습이 없을 때만 돌립니다.

## 틀린 문장

**잘못 거른 문장(r2, 12개)** 은 대부분 편리함·휴대성을 말하는 꾸밈말이거나, 근거를 바꿔 말한 문장입니다.

- "편하게 쓰는 데일리 토트백", "편하게 들고 다니는 데일리 가방이 되세요.", "편안하게 채소 얇게 썰기"
- "가볍게 들기 좋은: … 손이나 어깨에 부담 없이 들고 다닐 수 있어요"(근거: 가볍게 들기 좋은)
- "접이식 프레임: 필요할 때만 펼치고, 사용하지 않을 때는 접어서 보관합니다."
- "세로 골지 무늬: 골지 짜임이 있어 질감이 살아납니다."

r1은 여기에 "사용 전 확인해주세요" 같은 내용 없는 안내 제목과 "간편하게 드실 수 있어요" 같은 문장을 더 걸렀습니다. 다시 매기기로 이런 경우는 줄었지만(잘못 거르기 20 → 12) 다 없어지지는 않았습니다.

**놓친 문장(r2, 10개)** 은 근거에 없는 효과·느낌을 사실처럼 말한 문장입니다. 예: "아침마다 일어나는 물 튀는 소음과 젖은 바닥에 대한 불안감을 덜어줍니다.", "작은 밀폐 용기에서 집의 정리 정돈이 달라집니다.", "2 칸 분리 보관: 속옷과 양말을 따로 담아 혼선을 없애줍니다."

## 뜻하는 것

- 9B는 이 판정 일을 배웁니다. 재현율은 두 배 가까이 올랐습니다. 남은 문제는 정답이 편리함 꾸밈말·바꿔 말하기를 근거 없음으로 매기는 쪽으로 치우친 것이고, 모델은 그 치우침도 같이 배웁니다. r1 → r2에서 지시문만 고쳐도 잘못 거르기가 40% 줄었습니다.
- 런타임에서 거른 문장은 도구 오류("근거 없는 주장 …")가 되어 모델이 문장을 빼거나 사용자에게 묻습니다. 잘못 거르기 0.135면 근거 있는 문장 7~8개 중 하나가 막히므로, 기준을 지키는 것이 맞습니다.

## 다음 시도

1. **r3 정답 다시 매기기(권장).** 판정 회귀의 두 문장과 위 12개처럼 편리함 꾸밈말("편하게 쓰는", "편안하게 썰기")과 근거에서 바로 따라 나오는 말("이중 진공 단열" → "따뜻함이 오래가요")을 근거 있음으로 매기도록 지시문을 고칩니다. 그 뒤 r2 데이터의 근거 없음 문장을 다시 매기고, 같은 설정으로 학습합니다. Codex 사용량이 들고, 학습은 약 3시간입니다.
2. **문턱값 조절.** `"supported": false`를 낼 확률이 높을 때만 거르게 하면, 재현율을 조금 내주고 잘못 거르기를 줄일 수 있습니다. MLX Serve의 logprobs 지원 여부부터 확인해야 하고, `agent.judge`가 바뀝니다.
3. **기준을 바꿔 r2를 채택.** 근거 없는 문장을 더 잡는 대신 근거 있는 문장이 더 막히는 것을 받아들이는 경우입니다. 이는 제품 결정이라 사용자가 정합니다.

병합한 모델 `local/Qwen3.8-9B-pagegen-judge-r1-8bit`, `local/Qwen3.8-9B-pagegen-judge-r2-8bit`(각 9.7GB)는 MLX Serve 모델 폴더에 남겨 두었습니다. `JUDGE_MODEL=local/Qwen3.8-9B-pagegen-judge-r2-8bit uv run python -m pagegen.server`로 직접 써 볼 수 있습니다.
